# 项目计划插件接口文档

---

## 一、插件概述

| 属性 | 值 |
|------|-----|
| 插件名称 | `project_plan` |
| 插件版本 | `1.0.0` |
| 接口前缀 | `/api/project_plan` |
| 功能描述 | 解析项目进度表 Excel 文件，按主线分组提取电子内部发测/整车发测的 SOP、OTA 阀点周期数据，并筛选未来三个月内即将进行的整车发测任务 |

---

## 二、接口总览

| 接口路径 | 方法 | 说明 |
|---------|------|------|
| `/api/project_plan/create_plan` | POST | 上传并解析项目进度表 Excel 文件 |

---

## 三、统一响应格式

所有接口均采用以下统一响应格式：

```json
{
  "code": 200,
  "message": "解析成功",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码，200 表示成功，400 表示失败 |
| message | string | 响应消息 |
| data | object/array/null | 业务数据，失败时为 null |

---

## 四、前置条件

### 4.1 文件要求

| 条件 | 说明 |
|------|------|
| 文件格式 | 仅支持 `.xlsx` 格式（Excel 2007+） |
| 文件位置 | 必须放置在服务端 `uploads/` 目录下 |
| 文件权限 | 服务端进程需具备读取权限 |
| 传入参数 | 传入 `file_path` 为 `uploads/` 目录下的**相对文件名**（如 `项目进度表_2026.xlsx`） |

### 4.2 Excel 表结构要求

| 区域 | 列位置 | 说明 |
|------|--------|------|
| A 列 | 第 1 列 | 主线名称（如 P101、P102），支持合并单元格 |
| B 列 | 第 2 列 | 细分任务名称（如"电子内部发测"、"整车发测"） |
| C 列及之后 | 第 3 列起 | 阀点周期表头（如 `2026.1.W3`），每个单元格填入 SOP/OTA 等阀点内容 |

### 4.3 数据过滤规则

| 过滤维度 | 过滤值 | 说明 |
|---------|--------|------|
| 任务过滤（task_filter） | `["电子内部发测", "整车发测"]` | 仅解析这两种细分任务的数据 |
| 单元格过滤（cell_filter） | `["SOP", "OTA"]` | 单元格内容包含 SOP 或 OTA 关键词才会被收录 |

## 五、接口详情

### 5.1 创建/解析项目计划

**接口路径：** `/api/project_plan/create_plan`

**请求方法：** `POST`

**请求参数（Query/String）：**

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| file_path | string | Query | 是 | `uploads/` 目录下的 Excel 文件相对路径，仅支持 `.xlsx` 格式 |

> **注意：** 该接口是 `POST` 方法，参数 `file_path` 作为查询字符串（Query Parameter）传入，而非 Body JSON。例如：`POST /api/project_plan/create_plan?file_path=项目进度表_2026.xlsx`

**请求示例：**

```
POST /api/project_plan/create_plan?file_path=项目进度表_2026.xlsx
```

**缓存机制：**

| 属性 | 值 |
|------|-----|
| Redis 缓存键 | `project_plan:{file_path}` |
| 缓存有效期 | 20 分钟 |
| 缓存行为 | 若同名文件在 20 分钟内已被解析过，直接返回缓存数据，不会重复解析 |

## 六、数据结构说明

### 6.1 all_data 数组元素结构

```json
{
  "主线": "string (主线名称，如 P101、P102)",
  "电子内部发测": {
    "SOP": ["2026.5.W3", "2026.6.W1"],
    "OTA": ["2026.7.W2"]
  },
  "整车发测": {
    "SOP": ["2026.6.W2"],
    "OTA": ["2026.8.W1"]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| 主线 | string | 项目主线名称，取自 Excel A 列 |
| 电子内部发测 | object | 该主线"电子内部发测"任务的阀点数据，key 为 SOP/OTA，value 为对应阀点周期数组 |
| 整车发测 | object | 该主线"整车发测"任务的阀点数据，key 为 SOP/OTA，value 为对应阀点周期数组 |
| SOP | array[string] | SOP 阀点对应的周期列表，格式为 `{年}.{月}.W{周}` |
| OTA | array[string] | OTA 阀点对应的周期列表，格式为 `{年}.{月}.W{周}` |

### 6.2 阀点周期格式

格式：`{年}.{月}.W{周号}`

周号划分规则（按自然月的日划分）：

| 日期范围 | 周号 |
|---------|------|
| 1 日 ~ 6 日 | W1 |
| 7 日 ~ 14 日 | W2 |
| 15 日 ~ 23 日 | W3 |
| 24 日 ~ 月末 | W4 |

示例：`2026.6.W3` 表示 2026 年 6 月第 3 周（15 日 ~ 23 日）。

### 6.3 排序规则

`all_data` 数组按以下规则排序：

1. 有 `整车发测` 数据的主线：比较其 SOP + OTA 所有阀点周期，取**最早**的时间，按时间升序排列（时间越早越靠前）
2. 没有 `整车发测` 数据的主线：排在列表最后

### 6.4 upcoming_vehicle_tasks 筛选规则

从 `all_data` 中筛选出满足以下条件的项目：

- 该项目在 `整车发测` 中存在至少一条 SOP 或 OTA 阀点，且阀点周期落在**当前日期起 3 个月内**（含当前月和未来三个月）
- 符合条件的项目会**完整返回**（包含其所有任务数据：电子内部发测 + 整车发测）

## 八、技术实现说明

### 8.1 解析流程

```
请求 file_path
    │
    ├─ 拼接完整路径: settings.UPLOAD_DIR / file_path
    ├─ 校验: 文件存在 → .xlsx后缀 → 可读权限
    │
    ├─ Redis缓存检查: project_plan:{file_path}
    │   └─ 命中 → 直接返回缓存数据
    │
    └─ 解析Excel (asyncio.to_thread 线程池)
        ├─ 第1行: 读取阀点周期表头 (C列起)
        ├─ 合并单元格: 预解析主线名称映射
        ├─ 逐行遍历:
        │   ├─ 确定主线 (合并单元格/直接读取A列)
        │   ├─ 确定细分任务 (B列)
        │   ├─ task_filter 过滤 (仅"电子内部发测"/"整车发测")
        │   ├─ 遍历阀点周期列
        │   └─ cell_filter 过滤 (仅含SOP/OTA的单元格)
        ├─ 按整车发测最早阀点排序
        ├─ 筛选未来3个月整车发测任务
        └─ 存入Redis缓存 (TTL 20分钟)
```

### 8.2 周号计算逻辑

当前日期用于计算"未来三个月"范围：

```python
# 例：当前日期 2026-06-18
date_to_week_str(2026-06-18)  →  "2026.6.W3"   (15-23日 → W3)
date_to_week_str(2026-09-18)  →  "2026.9.W3"   (三个月后)
```

筛选范围：`["2026.6.W3" ≤ 阀点周期 ≤ "2026.9.W3"]` 内的整车发测任务。
