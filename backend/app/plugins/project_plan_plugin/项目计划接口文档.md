# 项目计划插件接口文档

---

## 一、插件概述

| 属性 | 值 |
|------|-----|
| 插件名称 | `project_plan` |
| 插件版本 | `1.0.0` |
| 接口前缀 | `/api/project_plan` |
| 功能描述 | 解析项目进度表 Excel 文件，按主线分组提取电子内部发测/整车发测的 SOP、OTA 阀点周期数据及具体日期，并筛选未来三个月内即将进行的整车发测任务 |

---

## 二、接口总览

| 接口路径 | 方法 | 说明 |
|---------|------|------|
| `/api/project_plan/upload_planfile` | POST | 分片上传项目进度表 Excel 文件 |
| `/api/project_plan/create_plan` | POST | 解析已上传的项目进度表 Excel 文件 |

---

## 三、统一响应格式

所有接口均采用以下统一响应格式：

```json
{
  "code": 200,
  "message": "解析成功",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码，200 表示成功，400 表示失败 |
| message | string | 响应消息 |
| data | object/array/null | 业务数据，失败时为 null |

---

## 四、前置条件

### 4.1 文件要求

| 条件 | 说明 |
|------|------|
| 文件格式 | 仅支持 `.xlsx`、`.xls` 格式 |
| 文件位置 | 通过 `upload_planfile` 接口上传至 `uploads/project_plan/` 目录 |
| 文件权限 | 服务端进程需具备读取权限 |
| 传入参数 | `create_plan` 接口传入 `file_path` 为 `uploads/project_plan/` 目录下的**相对文件名**（如 `项目进度表.xlsx`） |

### 4.2 Excel 表结构要求

| 区域 | 列位置 | 说明 |
|------|--------|------|
| A 列 | 第 1 列 | 主线名称（如 P101、P102），支持合并单元格 |
| B 列 | 第 2 列 | 细分任务名称（如"电子内部发测"、"整车发测"） |
| C 列及之后 | 第 3 列起 | 阀点周期表头（如 `2026.1.W3`），单元格填入具体阀点内容，如 `SOP+1 5/8发测` 或 `OTA 6/20` |

### 4.3 数据过滤规则

| 过滤维度 | 过滤值 | 说明 |
|---------|--------|------|
| 任务过滤（task_filter） | `["电子内部发测", "整车发测"]` | 仅解析这两种细分任务的数据 |
| 单元格过滤（cell_filter） | `["SOP", "OTA"]` | 单元格内容包含 SOP 或 OTA 关键词才会被收录 |

## 五、接口详情

### 5.1 分片上传文件

**接口路径：** `/api/project_plan/upload_planfile`

**请求方法：** `POST`

**Content-Type：** `multipart/form-data`

**请求参数：**

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| file | file | FormData | 是 | 当前分片的文件二进制数据 |
| fileMd5 | string | FormData | 是 | 完整文件的 MD5 值，用于分片分组和去重 |
| chunkIndex | int | FormData | 是 | 当前分片索引，从 0 开始 |
| totalChunk | int | FormData | 是 | 总分片数 |
| totalSize | int | FormData | 是 | 完整文件总大小（字节） |

**请求示例：**

```
POST /api/project_plan/upload_planfile
Content-Type: multipart/form-data

file: (binary)
fileMd5: d41d8cd98f00b204e9800998ecf8427e
chunkIndex: 0
totalChunk: 5
totalSize: 1048576
```

**响应示例：**

分片未全部上传完成时：
```json
{
  "code": 200,
  "message": "分片 0 上传成功",
  "uploaded": [0, 1, 2],
  "merged": false
}
```

全部分片上传完成并合并后：
```json
{
  "code": 200,
  "message": "文件上传并合并完成",
  "file_url": "/uploads/project_plan/项目进度表_2026.xlsx",
  "merged": true
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| uploaded | array[int] | 已上传的分片索引列表 |
| merged | bool | 是否已完成合并，true 表示文件已就绪 |
| file_url | string | 合并完成后返回的文件访问路径 |

**上传流程：**

1. 前端将文件分片，每片调用一次本接口
2. 所有分片上传完成后，服务端自动合并为完整文件
3. 若同名文件已存在，自动覆盖
4. 合并完成后即可调用 `create_plan` 接口解析

### 5.2 创建/解析项目计划

**接口路径：** `/api/project_plan/create_plan`

**请求方法：** `POST`

**请求参数（Query/String）：**

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| file_path | string | Query | 是 | `uploads/project_plan/` 目录下的 Excel 文件相对路径，仅支持 `.xlsx` 格式 |

> **注意：** 该接口是 `POST` 方法，参数 `file_path` 作为查询字符串（Query Parameter）传入，而非 Body JSON。例如：`POST /api/project_plan/create_plan?file_path=项目进度表.xlsx`

**请求示例：**

```
POST /api/project_plan/create_plan?file_path=项目进度表.xlsx
```

**缓存机制：**

| 属性 | 值 |
|------|-----|
| Redis 缓存键 | `project_plan:{file_path}` |
| 缓存有效期 | 20 分钟 |
| 缓存行为 | 若同名文件在 20 分钟内已被解析过，直接返回缓存数据，不会重复解析 |

---

#### 5.2.2 成功响应（缓存命中）

当同一文件在 20 分钟缓存有效期内再次请求时，直接返回缓存数据：

```json
{
  "code": 200,
  "message": "数据已存在",
  "data": {
    "all_data": [ ... ],
    "upcoming_vehicle_tasks": [ ... ]
  }
}
```

---

#### 5.2.3 错误响应

| 状态码 | 响应体 | 触发条件 |
|--------|--------|----------|
| 400 | `{"code": 400, "message": "文件不存在", "data": null}` | `uploads/project_plan/` 目录下找不到指定文件 |
| 400 | `{"code": 400, "message": "仅支持.xlsx格式文件", "data": null}` | 文件后缀名不是 `.xlsx` |
| 400 | `{"code": 400, "message": "文件无读取权限", "data": null}` | 服务端进程无文件读取权限 |
| 400 | `{"code": 400, "message": "文件解析失败：{详细错误}，请重试。", "data": null}` | Excel 文件损坏、格式异常或 openpyxl 解析异常 |

## 六、数据结构说明

### 6.1 all_data 数组元素结构

```json
{
  "项目": "string (主线名称，如 A10-钱浩-T1/T2/T3、P102)",
  "电子内部发测": {
    "SOP": ["2026.1.W4: 1/19"],
    "OTA": ["2026.3.W2: 3/15"]
  },
  "整车发测": {
    "SOP": ["2026.1.W4: 1/28"],
    "OTA": ["2026.3.W2: 3/15"]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| 项目 | string | 项目主线名称，取自 Excel A 列 |
| 电子内部发测 | object | 该主线"电子内部发测"任务的阀点数据，key 为 SOP/OTA |
| 整车发测 | object | 该主线"整车发测"任务的阀点数据，key 为 SOP/OTA |
| SOP | array[string] | SOP 阀点对应的周期列表，格式为 `{年}.{月}.W{周}: {月/日}` |
| OTA | array[string] | OTA 阀点对应的周期列表，格式为 `{年}.{月}.W{周}: {月/日}` |

### 6.2 阀点周期格式

格式：`{年}.{月}.W{周号}: {月/日}`

每个阀点周期附带具体的日期信息，从单元格值中提取。例如：

| 单元格值 | 提取结果 |
|---------|---------|
| `SOP+1 5/8发测` | `2026.5.W2: 5/8` |
| `OTA 6/20` | `2026.6.W3: 6/20` |
| `SOP`（无具体日期） | `2026.6.W3`（仅周期，无日期后缀） |

周号划分规则（按自然月的日划分）：

| 日期范围 | 周号 |
|---------|------|
| 1 日 ~ 6 日 | W1 |
| 7 日 ~ 14 日 | W2 |
| 15 日 ~ 23 日 | W3 |
| 24 日 ~ 月末 | W4 |

### 6.3 排序规则

`all_data` 数组按以下规则排序：

1. 有 `整车发测` 数据的主线：提取其 SOP + OTA 所有条目中的**实际日期**（如 `2026.1.W4: 1/28` → 2026年1月28日），取**最早**的日期，按日期升序排列（日期越早越靠前）
2. 没有 `整车发测` 数据的主线：排在列表最后
3. 若无具体日期，则回退到按阀点周期（年、月、周）比较

### 6.4 upcoming_vehicle_tasks 筛选规则

从 `all_data` 中筛选出满足以下条件的项目：

- 该项目在 `整车发测` 中存在至少一条 SOP 或 OTA 条目，且条目的**实际日期**（如 `2026.1.W4: 1/28` → 2026年1月28日）落在**当前日期起 3 个月内**（含当天）
- 符合条件的项目会**完整返回**（包含其所有任务数据：电子内部发测 + 整车发测）
- 若无具体日期，则回退到按阀点周期比较

## 七、依赖服务

| 服务 | 用途 |
|------|------|
| Redis | 缓存已解析的项目计划数据（TTL 20 分钟），以及分片上传的分布式锁协调 |

## 八、调用流程

```
1. 上传文件
   POST /api/project_plan/upload_planfile  （分片多次调用，直到 merged: true）

2. 解析文件
   POST /api/project_plan/create_plan?file_path=项目进度表_2026.xlsx

3. 获取结果
   → 200: all_data（全部项目）+ upcoming_vehicle_tasks（未来三个月内整车发测项目）
```
