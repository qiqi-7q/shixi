# 测试记录插件接口文档

---

## 一、接口总览

所有接口前缀：`/api/test_record`

| 接口路径                                        | 方法     | 说明             |
|---------------------------------------------|--------|----------------|
| `/api/test_record/createrecord`             | POST   | 创建单条测试记录       |
| `/api/test_record/fixsearch`                | GET    | 获取记录列表（固定字段查询） |
| `/api/test_record/getrecord/{record_id}`    | GET    | 获取单条记录详情       |
| `/api/test_record/updaterecord/{record_id}` | PUT    | 更新测试记录         |
| `/api/test_record/delrecord/{record_id}`    | DELETE | 删除测试记录         |
| `/api/test_record/batch_import`             | POST   | 批量本地Excel数据导入  |
| `/api/test_record/refresh_link`             | POST   | 刷新数据链接（定时任务）   |

---

## 二、统一响应格式

所有接口均采用以下统一响应格式：

```json
{
  "code": 200,
  "data": <业务数据或null>,
  "message": "响应消息"
}
```

| 字段      | 类型                | 说明                    |
|---------|-------------------|-----------------------|
| code    | int               | 状态码，200 表示成功，400 表示失败 |
| data    | object/array/null | 业务数据，失败时为 null        |
| message | string            | 响应消息                  |

### 4.6 批量本地Excel数据导入

**接口路径：** `/api/test_record/batch_import`

**请求方法：** `POST`

**请求参数：**

| 参数名  | 类型     | 位置    | 必填 | 说明                 |
|------|--------|-------|----|--------------------|
| path | string | Query | 是  | Excel文件的本地**绝对路径** |

> **说明：** 此接口用于从服务器本地路径读取 Excel 文件（`.xlsx` 格式），批量导入测试记录数据。自动进行数据去重、格式校验和批量写入。

**请求示例：**

```
POST /api/test_record/batch_import?path=D:/data/test_records.xlsx
```

**成功响应：**

```json
{
  "msg": "批量导入完成",
  "total_excel_rows": 150,
  "excel_duplicate_rows": 5,
  "db_duplicate_rows": 10,
  "success_import_rows": 135,
  "failed_import_rows": 0
}
```

**响应字段说明：**

| 字段                   | 类型     | 说明                      |
|----------------------|--------|-------------------------|
| msg                  | string | 导入结果消息                  |
| total_excel_rows     | int    | Excel读取的有效数据总行数（过滤全空行后） |
| excel_duplicate_rows | int    | Excel内过滤的重复行数           |
| db_duplicate_rows    | int    | 数据库已存在的重复行数             |
| success_import_rows  | int    | 最终成功导入的新数据行数            |
| failed_import_rows   | int    | 导入失败的行数                 |

**错误响应：**

| 情况      | 返回内容     | 说明                         |
|---------|----------|----------------------------|
| 参数类型错误  | 字符串错误消息  | 第一个参数必须是文件路径字符串            |
| 文件读取失败  | 字符串错误消息  | Excel数据处理失败：...            |
| 无有效数据   | JSON对象   | `{"msg": "无有效数据可导入", ...}` |
| 数据格式错误  | HTTP 400 | `第N行数据格式错误：...`            |
| 数据库写入失败 | HTTP 400 | `数据库写入失败：...`              |

## 五、批量导入处理流程

```
Excel文件（本地绝对路径）
    │
    ▼
读取Sheet1 ──── 过滤全空行 ──── 处理表头（空值/重名）
    │
    ▼
第一重去重：内存去重（基于 vin_code + problem_time + problem_desc）
    │           过滤Excel内部的重复数据
    ▼
第二重去重：数据库去重（基于相同字段组合）
    │           过滤数据库中已存在的重复数据
    ▼
数据校验：转Pydantic模型，确保格式符合Schema
    │
    ▼
批量写入数据库（bulk_insert_mappings）
    │
    ▼
返回导入结果统计
```

### 5.1 去重规则

通过 `vin_code`、`problem_time`、`problem_desc` 三个字段组合判定数据是否重复，三者均相同视为重复数据。

### 5.2 Excel 文件要求

| 要求项  | 说明             |
|------|----------------|
| 文件格式 | `.xlsx`        |
| 工作表名 | `Sheet1`（默认读取） |
| 表头行  | 第 1 行为表头       |
| 数据行  | 第 2 行起为数据      |
| 空行处理 | 全空行自动过滤        |

### 5.3 表头字段映射

| Excel表头            | 对应字段                   | 是否必填 |

## 八、注意事项

### 8.1 响应格式统一

所有接口响应格式为 `{"code": 200, "data": ..., "message": "..."}`，字段顺序为 code → data → message。

### 8.2 批量导入异步兼容性问题

`batch_import_records` 函数中使用了同步的 `db.query()` 和 `db.bulk_insert_mappings()` 方法，但接口声明为 `async`。在纯异步模式下可能导致事件循环阻塞，建议在高并发场景下改为同步接口或使用异步 ORM 方法。

### 8.3 批量导入路径安全

`batch_import` 接口直接接收本地文件路径，未做路径合法性校验。建议在生产环境中增加路径白名单或上传文件机制，防止目录遍历攻击。

### 8.4 fixsearch 接口排序

`fixsearch` 接口默认按 `id` 降序排列（最新创建的记录在前），支持分页参数 `skip` 和 `limit`，并返回 `total` 字段用于前端分页计算。

## 九、刷新数据链接接口

### 9.1 刷新数据链接

**接口路径：** `/api/test_record/refresh_link`

**请求方法：** `POST`

**功能说明：** 根据数据库中已有的 VIN 号和问题时间，从外部 API（数据集 1963 和 6868888）获取 bag 数据链接并更新 `data_link` 字段。支持手动触发和定时任务自动执行（每 10 分钟）。

**请求参数：** 无

**请求示例：**

```
POST /api/test_record/refresh_link
```

**成功响应：**

```json
{
  "code": 200,
  "data": {
    "success": true,
    "total_records": 100,
    "success_count": 85,
    "fail_count": 5,
    "no_match_count": 10
  },
  "message": "刷新成功"
}
```

**响应字段说明：**

| 字段            | 类型  | 说明                     |
|-----------------|-------|--------------------------|
| success         | bool  | 是否成功                 |
| total_records   | int   | 处理的记录总数           |
| success_count   | int   | 成功匹配并更新链接的记录数 |
| fail_count      | int   | 处理过程中异常的记录数   |
| no_match_count  | int   | 未匹配到任何链接的记录数 |

**错误响应：**

```json
{
  "code": 400,
  "data": null,
  "message": "未能获取到bag数据，请检查token是否有效"
}
```

**错误消息说明：**

| 错误消息                    | 说明                     |
|-----------------------------|--------------------------|
| 未找到需要刷新链接的记录    | 数据库中无符合条件的记录 |
| 未能获取到bag数据           | 外部 API 调用失败        |

### 9.2 定时任务配置

| 配置项       | 值                     | 说明                     |
|--------------|------------------------|--------------------------|
| 执行间隔     | 10 分钟               | 可在 `plugin.py` 中修改 |
| 日志文件     | `scheduler.log`       | 位于插件目录下           |
| 日志清空     | 每次重启自动清空       | -                        |

**定时任务日志示例：**

```

2026-06-18 10:30:00,456 - INFO - 定时任务调度器已启动
2026-06-18 10:40:00,789 - INFO - 开始执行定时任务：刷新数据链接
2026-06-18 10:40:01,234 - INFO - 定时任务执行成功: 总数=100, 成功=85, 失败=0, 未匹配=15
```

### 9.3 匹配逻辑

1. **数据来源**：从两个数据集获取 bag 数据
   - 数据集 1963（上位机数据集）
   - 数据集 6868888（车机数据集）

2. **匹配规则**：
   - 分别匹配数据集 1963 和 6868888 的链接
   - 如果两个数据集都匹配到链接，用逗号分隔后合并存入 `data_link`
   - 如果只有一个数据集匹配到，只存入该链接
   - 如果都未匹配到，设置为 `None`

3. **匹配条件**：基于 VIN 号和问题时间进行匹配
